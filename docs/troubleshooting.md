# 连接检查与恢复

## 日常连接

家里 Mac 保持联网、唤醒、Orca 共享开启，反向 SSH 后台连接持续运行。工作端打开 Orca，使用已有原生 SSH 绑定，然后执行 `./work-tunnel status`。

原生 SSH 的本地端口由 Orca 动态分配，不能把某一次观察到的端口写死到配置中。

## 设备运行实例身份变化

状态检查会分别核对配对设备身份与运行实例身份。远端升级或重启可能伴随运行实例变化，但身份报错也可能来自配置错误，不能只凭 IP 或主机名称自动改写记录。

先在 Orca 界面断开并重新连接已有远程设备。仍有异常时核对双方版本、原有配对设备、公钥和会话；需要修复本机绑定记录时先备份，按当前 Orca 版本的行为处理。本工具不会自动写入绑定数据。

保留已有设备、项目和会话，不用删除配对来代替诊断。

## 手动备用通道

1. 执行 `./work-tunnel backup-start` 并检查 HTTP 可达。
2. 在工作端 Orca 的远程连接设置里手动选择对应备用入口。部分版本需要先停止该设备的原生 SSH 入口；界面操作以当前安装版本为准。
3. 使用已有配对验证实际的项目和会话访问。HTTP 可达不足以证明配对正常。
4. 原生 SSH 恢复并验证通过后，执行 `./work-tunnel backup-stop`。

备用脚本只控制自己 SSH 配置中的 ControlMaster，不会自动切换 Orca、修改配对或停止原生主通道。

## 家里端检查

家里端日志默认在 `~/Library/Application Support/Orca SSH Relay/home.stderr.log`。先确认本机 Orca 服务可达，再检查主机公钥、公钥登记、账户转发策略和网络。

准备脚本不覆盖已有配置。需要调整时，先保留原文件并人工核对差异，避免重新生成密钥造成已登记公钥失效。
